### 3 条记录
1. Responses API 用 instructions + input；JSON mode 走 text.format；usage 字段是 input_tokens / output_tokens
2. enable_thinking=True 与 JSON mode 互斥，同时开报 400 InvalidParameter；
   关闭后 reasoning_tokens=0 可验证
3. schema 约束是成本与正确性的双重闸门：同任务下 out 从 167 降到 84；
   更严重的是无 schema 时模型编造了完整订单（假物流单号、假商品清单）

### 一个技术判断
- 意图分类不需要 thinking，周四 llm_client.py 默认不传 enable_thinking
- prompt 模板必须显式给字段名和类型，否则模型自由发挥 → token 翻倍 + 幻觉
- 业务数据必须来自工具调用（W7 的查订单工具），LLM 只做意图理解和组织语言，
  绝不能让它「生成」订单详情

## Day 4 · 10/22 · 主链路打通（config / loader / llm_client / main）

| 项目 | 值 |
|---|---|
| 目标 | txt → JSON 端到端，一条命令 |
| 结果 | `uv run llm-cli parse data/a.txt` → `out/a.json` |

| 代码量 | config 53 / loader 49 / llm_client 42 / main 103，核心合计 247 行 |
| 入口 | `uv run llm-cli` 与 `uv run python -m llm_cli` 双通 |

### 四个模块的分工

| 文件 | 职责 | 它不知道什么 |
|---|---|---|
| `config.py` | .env → Settings，缺 Key 就 exit 1 | 不知道有文件、有模型 |
| `loader.py` | 文件 → Document(text, meta) | 不知道有模型；**也不依赖 config** |
| `llm_client.py` | 一段话 → 模型回的原始字符串 | 不知道有文件，不解析 JSON |
| `main.py` | 串流程 + CLI + 落盘 | —— |

依赖单向：`main → 三者`，`llm_client → config`。**没有回指箭头**，所以底层可以单独测试、单独替换。

### 踩过的 4 个坑

1. **`python -m llm_cli` 报 `No module named llm_cli.__main__`**
   包被当作程序执行时找的是 `__main__.py`，不是 `main.py`。补 4 行转发即可。

2. **`"__main__"` 被复制成 `"__&#8203;main__"`**
   零宽空格实体，肉眼完全不可见 → `if` 恒为假 → **程序静默退出、退出码 0、无任何报错**。
   修复：`(Get-Content 文件 -Raw) -replace '&#8203;','' | Set-Content 文件 -Encoding ascii`。
   教训：关键标识符手打，别复制。

3. **`Settings.base_url="...",` → 报 `got <class 'tuple'>`**
   两个错叠加：① 缺 `: str` 注解，`@dataclass` 只认带注解的名字，否则只是普通类属性、不进 `__init__`；② 尾逗号把字符串变成单元素元组。

4. **400：`'messages' must contain the word 'json'`**
   百炼在 JSON 模式下要求 prompt 里必须出现 "json" 字样（OpenAI 原生没这条）。测试 prompt 没含，误判成代码 bug，白查一轮。

### 一个技术判断

- **400 被重试 3 次是纯浪费。** 重试只该针对超时 / 429 / 5xx；4xx 是请求本身错了，重试多少次结果都一样。周五把 `except OpenAIError` 拆两支。
- **`responses.create` 有可移植性风险。** OpenAI 官方推荐新项目用它，但 vLLM / Ollama / DeepSeek 这类只实现 Chat Completions。将来换厂商要改的只是 `complete()` 一个方法——**这正是 llm_client 这一层存在的意义**。
- **编码问题的判断方向**：文件用编辑器打开正常、终端显示乱码 → 是 PowerShell 的 `Get-Content` 按 GBK 解码 UTF-8 文件，**不是文件坏了**。用 `-Encoding UTF8` 或 `chcp 65001`。
