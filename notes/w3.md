# W3 笔记（11/02–11/08 · 阶段 1 RAG）

## Day 1（周一 11/02）· ch2 数据准备 + RAG 链路

### RAG 五段链路（不翻书复述版）
1. 加载：原始文档(PDF/TXT/MD) → 纯文本字符串
2. 切分：长文本 → N 个带边界的短块(chunk)
3. 向量化：每个 chunk 文本 → 1024 维浮点向量（qwen3.7-text-embedding-flash）
4. 存储：向量+原文+元数据 → 向量库(Chroma 本地文件)
5. 检索：query → top-K 个 {text, source, score}

> 本周(W3)只做这五段；生成(模型照着检索结果回答)是第⑥段，W4 才接。
> RAG = Retrieval 检索 + Augmentation 把原文塞进 prompt + Generation 模型照答。

### ch2 三行笔记
- **解决什么**：长文档不能整篇塞给模型，得切成能被检索的小块；切分策略+chunk_size/overlap 决定检索质量。
- **改我哪行**：周四 chunking 函数第一版由我写——固定长度切分 + overlap，参数 chunk_size=512、overlap=50 起步，周六做 256/512/1024 三档对照。
- **哪里不懂**：语义切分(用 embedding 算相邻句相似度在跳变处切)成本多高、值不值得本周上？——倾向 W4 再评估，本周只做固定长度。

### 切分策略三档（糙→精）
- 固定长度：按字符/token 硬切，简单但截断句子。本周做这个。
- 按句子/段落：用句号/换行当边界，块长不均但语义完整。
- 语义切分：embedding 算相邻句相似度，跳变处切，质量最高成本最高。W4/W5 再说。

### 两个参数
- chunk_size：每块大小，256–1024 token，默认 512。小=精度升上下文碎；大=上下文全噪声多。没有一刀切，要实测。
- overlap：相邻块重叠，防边界丢信息，取 chunk_size 的 10%–20%（512 配 50–100）。

### 一手直觉（面试弹药）
「512 不是万能答案」——问答偏小块、摘要偏大块，必须用真实问题跑召回对照才能定。周六三档实验就是为这个。

### 对照真书补正（11/03 晚，读 all-in-rag ch2/05 原文后）
**分块策略其实是四种，我 Day1 只讲了三种，漏了两种关键的：**
- 递归字符分块 `RecursiveCharacterTextSplitter`：LangChain 默认方案，用层级分隔符 `["\n\n","\n","。","，"," ",""]` 递归切，先段落再句子再字符，尽量沿语义边界。**周四第一版抄这个简化版**，别写死固定长度。
- 基于文档结构 `MarkdownHeaderTextSplitter`：按 Markdown 标题层级切，块带「标题路径」元数据。**我们的语料条目编号就是 ## 标题，天然适合**——一个 chunk=一个条目，source 直接是条目号。留 W4 优化。
-（固定大小 / 语义分块 之前讲过，语义分块用 embedding 算相邻句距离、在跳变处切，书里 4 种断点识别法：percentile/std/iqr/gradient）

**「块不能太大」的三个硬理由（比我说的「噪声多」具体，面试弹药）：**
1. embedding 池化信息损失：所有 token 压成一个向量，块越长向量越稀释越笼统，检索精度降。
2. Lost in the Middle：LLM 处理长上下文记得住头尾、忘中间（有论文 Liu et al. 2023）。
3. 主题稀释：一个块主题越多越杂，检索相关性分数越低越难精准召回。

**默认值纠正**：LangChain RecursiveCharacterTextSplitter 默认 chunk_size=4000 / overlap=200（不是 512/50）；书示例用 200/10。「256–1024 token、overlap 10–20%」是通用经验、书未背书——以周六实测为准。

## Day 3（周三 11/04）· ch3 向量嵌入节

### ch3 三行笔记
- **解决什么**：把文本变成能算相似度的向量；语义相似的向量距离近，不相关的远。
- **改我哪行**：周四 embedder.py 写两个时刻——入库时每个 chunk 向量化、查询时 query 向量化，必须同模型(qwen3.7-text-embedding-flash)。
- **哪里不懂**：qwen3.7-text-embedding-flash 的 max tokens 上限是多少？chunk_size 不能超过它，周四开工前查百炼文档确认。

### 三个相似度度量（面试常问）
- 余弦相似度：夹角余弦，越接近 1 越相似，**RAG 最常用**，Chroma 默认。
- 点积：归一化后等价余弦。
- 欧氏距离：直线距离，越小越相似。
> RAG 检索 = 算 query 向量与每个 chunk 向量的余弦相似度，取 top-K。

### embedding 的两个时刻（书 1.2.1 原文印证）
1. 离线建索引：chunk → 向量 → 存库
2. 在线查询：query → 向量（**同一模型**）→ 算相似度 → 取 top-K
> 不同模型的向量空间不同，距离没意义——这就是「必须同模型」的根。

### 硬约束
embedding 模型有 max tokens 上限，chunk_size 不能超过它（否则截断、向量不完整）。周四开工前查 qwen3.7-text-embedding-flash 的 max tokens。
